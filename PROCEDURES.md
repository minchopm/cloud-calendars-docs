# Cloud Calendars: Sync & Widget — operating procedures

Use these procedures as task-oriented reference. They describe public capabilities and verification steps, not private implementation. UI labels can vary by version.

## Procedure 1: Diagnose an apparently missing event

### Before you begin

Know the expected source calendar, time and date.

### Steps

1. Check that the correct account and calendar are selected.

2. Check the displayed date range, view and time zone.

3. Compare the event with the source account.

4. Check connectivity, permissions and synchronization status.

5. Open the app after changes instead of relying only on a widget.

### Expected result

You can distinguish a filtered/delayed view from an event missing at the source.

### If the result differs

A filtered calendar cannot establish availability. Check all-day events in the app if the widget shows only timed appointments.

## Procedure 2: Reschedule a repeating appointment

### Before you begin

Use an editable calendar and understand the recurrence scope.

### Steps

1. Open the intended occurrence.

2. Check whether the change applies to this occurrence or the series.

3. Change the time and verify time-zone interpretation.

4. Inspect neighboring occurrences for unintended changes.

5. Confirm the result in the source calendar and any participant notifications.

### Expected result

The intended occurrence or series changes without unintended moves.

### If the result differs

If the calendar is read-only, use the correct source/account; do not create a duplicate just to hide a permissions issue.

## Report a repeatable problem

Record app/version, device/OS, selected mode, input conditions and the smallest failing step. Distinguish expected behavior from the observed result. Use synthetic examples and omit credentials or private records.
